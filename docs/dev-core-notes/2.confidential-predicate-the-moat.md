# 2 — Confidential predicate: the moat, reproduced in-repo

Ported the proven Experiment 2 `confidential_predicate` into the monorepo and got
it passing on **real proofs** (`RISC0_DEV_MODE=0`). This is the irreplaceable
guarantee — a predicate over a shielded, commitment-bound balance — now living in
`predicate-engine/`, not just in the experiments repo.

## Result

```
running 2 tests
test confidential_predicate_fails_when_below_threshold - should panic ... ok
test confidential_predicate_passes_over_shielded_balance ... ok
test result: ok. 2 passed; finished in 86.67s
```

- **passes_over_shielded_balance** — real proof that a shielded balance of 5000
  clears the 1000 threshold; balance never in any public field.
- **fails_when_below_threshold** — `500 >= 1000` is unprovable: the guest panics,
  `execute_and_prove` returns `ProgramProveFailed`. The `should_panic` passing IS
  the soundness/unforgeability guarantee.

## What changed from the scaffold (and why)

The scaffold guessed at a custom `ConfidentialBalance` account type with a `Data`
bridge. **Wrong.** The proven Exp 2 predicate reads the account's **native
`balance` field** directly (`subject.account.balance`). So:

- `core` is just the `Instruction` enum + `serde`. No `#[account_type]`, no
  `TryFrom<&Data>` machinery.
- `src/check.rs` reads `subject.account.balance`, asserts `>= threshold`, returns
  `vec![AccountPostState::new(subject.account)]` (read-only — post-state == input).

## Load-bearing API facts (confirmed against nssa v0.2.0-rc3 source)

- `execute_and_prove(pre_states, instruction_data, visibility_mask, private_account_keys, private_account_nsks, private_account_membership_proofs, &program.into()) -> Result<(PrivacyPreservingCircuitOutput, Proof), NssaError>` — 7 args.
- For a single read-only shielded input: `pre_states = vec![subject_pre]`,
  `visibility_mask = vec![1]`, membership proof from
  `state.get_proof_for_commitment(&commitment)`.
- **Genesis seeding:** `V03State::new_with_genesis_accounts(&[], vec![(Commitment, Nullifier)], 0)`.
  The 2nd arg is genesis private accounts. **The paired nullifier must be
  `Nullifier::for_account_initialization(&npk)`, NOT the spend-nullifier** —
  otherwise the note is marked spent and the read fails confusingly at runtime.
- Private account nonce: `Nonce::private_account_nonce_init(&npk)`; post-state
  nonce increments via `.private_account_nonce_increment(&nsk)`.
- Commitment: `Commitment::new(&npk, &account)`.

## Build gotcha (macOS 26, Apple Silicon)

The guest cross-compile pulls `ring` as a host build-dep. `risc0_build` exports an
unscoped `CC=riscv-gcc`, which leaks into that host C build → Apple flags get fed
to the riscv compiler → fail. Fix: point host C at clang.

```
RISC0_DEV_MODE=0 \
  CC_aarch64_apple_darwin="$(xcrun --find clang)" HOST_CC="$(xcrun --find clang)" \
  cargo test -p integration_tests --test confidential_predicate -- --nocapture
```

(Baked into the `justfile` `build-guest` recipe. Linux needs none of this.)
