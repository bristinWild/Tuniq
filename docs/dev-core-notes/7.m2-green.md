## What the test proves

The test reads the consumer's `Registry` account directly after the transaction
and asserts `verified_count == 1`. This is not "no error thrown" - it's
unambiguous on-chain state change caused by the consumer CPI firing.

Full chain:


## Design decisions

**Consumer program as an account (not hardcoded).** `consumer_program` and
`consumer_registry` are passed as `UncheckedAccount` to `verify_predicate`. Any
program implementing `record_verification` can be wired in without redeploying
the coordinator. This is the SDK story in seed form - the coordinator is a
generic verified-proof router, not tied to one application.

**Counter over eligibility record.** The counter is the minimal, unambiguous proof
that the consumer was invoked. Real consumers gate access, mint tokens, or record
eligibility. The pattern is proven; the application logic is swappable.

**Consumer caller authorization.** The consumer's `RecordVerification` accounts
struct has a `caller: Signer<'info>` field. In the test, this is the payer (who
also signs the transaction). In production, constrain it:
```rust
#[account(constraint = caller.key() == COORDINATOR_ID)]
pub caller: Signer<'info>,
```
This ensures only the coordinator can invoke `record_verification`. Left flexible
for M2; tighten in M3.

## What carries into M3

**Nullifier binding** is the one deferred security gap. The coordinator accepts
any nullifier the caller supplies as long as the proof verifies. A caller could
supply an *unused* nullifier that isn't in this journal, and the coordinator would
create a PDA for it - effectively burning a fresh nullifier slot without it
meaning anything about this proof. The fix: decode the journal on-chain to extract
`new_nullifiers` from the `PrivacyPreservingCircuitOutput` and verify the supplied
nullifier matches. The risc0-serde encoding (word-aligned) means a substring scan
doesn't work (tried in M1); the correct approach is a proper deserializer.

**Dead code:** `journal_contains_nullifier` fn and `NullifierNotInJournal` error in
`coordinator/lib.rs` are unused. Remove when nullifier binding is implemented.

**Proving service:** `prover/` wraps a receipt to Groth16 but isn't callable. M3
turns it into an HTTP service with a defined request/response contract.

**Devnet:** everything has run in litesvm. M3 deploys coordinator + consumer to a
real Solana devnet.
