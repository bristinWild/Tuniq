# 8 - M3 GREEN: authorized prover + proving service

M3 closes the two pieces that carried from M2: the authorized prover security
constraint on the coordinator, and the proving service as a callable HTTP API.

## What landed

### Authorized prover constraint
`Config` gained `authorized_prover: Pubkey`. The coordinator's `initialize` now
takes this as an argument and stores it. `VerifyPredicate` constrains the `prover`
signer: `prover.key() == config.authorized_prover @ UnauthorizedProver`. Only the
registered prover service keypair can call `verify_predicate`.

This is the practical nullifier binding for M3: the prover service sees the
journal, extracts the correct nullifier, and must sign the transaction - so it
cannot supply a wrong nullifier without breaking its own signature. Consistent
with the litepaper trust model (trust-light, not trustless).

Dead code removed: `journal_contains_nullifier` fn and `NullifierNotInJournal`
error are gone from `coordinator/lib.rs`. Commit: `c6038f0`.

### Proving service
`prover/src/main.rs` refactored: the wrap logic is extracted into `pub fn wrap()`
and the service has two modes:

```
cargo run --release                    # one-shot (existing behavior)
cargo run --release --features serve -- serve  # HTTP service on :3000
```

API contract:
```
POST /wrap
{"proof_b64": "<base64 of proof.bin>", "image_id_hex": "<64 hex chars>"}

Response 200:
{"seal_b64": "<base64>", "journal_b64": "<base64>", "image_id_hex": "..."}
```

### Live test on x86 droplet
Tested on DigitalOcean x86 (4vCPU/8GB, Ubuntu, Docker 29.5.3):
- Build: 64m 34s cold
- Round-trip: ~90s (succinct receipt → Groth16 seal)
- Response: 256-byte seal, journal, image_id - all correct
- `image_id_hex` in response matches `PRIVACY_PRESERVING_CIRCUIT_ID`

The service received a real succinct receipt over HTTP, wrapped it to Groth16,
and returned a seal that the coordinator can verify on Solana. The full client
→ prover service → coordinator → consumer chain is now callable end to end.

## Config space note
`Config` space updated: `8 + 32 + 32 + 32 + 8 = 112` bytes
(discriminator + image_id + authority + authorized_prover + verified_count)

## What M3 deferred to M4
**Full on-chain nullifier binding.** The risc0-serde encoding wraps each `u8` as
a word-aligned `u32`, so the nullifier bytes are non-contiguous in the journal
(128 bytes spread across the encoded output). A substring scan doesn't work.
The rigorous fix - decoding `PrivacyPreservingCircuitOutput` on-chain - requires
either a risc0-serde decoder in BPF or a commitment scheme the prover generates
off-chain and the coordinator verifies cheaply. Deferred to M4.

**Fully stateless service.** The current service reads `artifacts/journal.bin`
from the local filesystem. M4 will include `journal_b64` in the request body
for full stateless operation.

**Devnet deployment.** Everything has run in litesvm and against a local droplet.
M4 deploys coordinator + consumer to a real Solana devnet. Requires `anchor keys
sync` on both programs before deployment.
