
## What's here

- `shared-types/` — the one cross-boundary contract (`EligibilityResult`),
  borsh-only so it can be depended on by the guest, the prover, and the Anchor
  coordinator without dragging conflicting toolchains together. The byte-layout
  test pins the exact 9-byte journal shape observed in Experiment 3.
- `predicate-engine/` — the confidential predicate, mirroring the lez-programs
  token program's three-crate shape:
  - `core/` — `Instruction` + `ConfidentialBalance` (via `#[account_type]`)
  - `.` (root crate `predicate_program`) — the `check_eligibility` handler
  - `methods/` — `risc0_build::embed_methods()`; exports the guest ELF + image ID
  - `methods/guest/` — the SPEL `#[lez_program]` guest (excluded from the workspace)

## Markers to resolve against the real nssa_core source

These compile in shape but mirror the token program — confirm the exact API:

1. `core/src/lib.rs` — `ConfidentialBalance` mirrors `TokenHolding`'s structure.
   Confirm your Experiment 2 shielded balance account carries `amount: u128`
   (or adjust).
2. `src/eligibility.rs` — `AccountPostState::unchanged(account)` is assumed for a
   read-only predicate. Token handlers build `AccountPostState` from mutated
   holdings; confirm the constructor for a no-mutation case (it may be a
   `Claim`-based form).

## Result surfacing (important, easy to get wrong)

On the fully-shielded path the predicate result is NOT a committed
`EligibilityResult` — it is assert-and-panic (proof exists ⇒ predicate held), and
the journal is the privacy circuit's output (commitments / nullifiers) which the
coordinator parses (Half B). `EligibilityResult` is the clean contract the
coordinator FORWARDS and the standalone/fast-lane guest commits. See the doc
comment in `shared-types/src/lib.rs`.
