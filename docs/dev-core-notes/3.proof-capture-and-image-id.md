# 3 — Proof capture to disk + the image-id correction (M0 prep)

Captured a real confidential-predicate proof to disk as the three artifacts the
succinct→Groth16 wrap step consumes. This is the first concrete M0 deliverable:
the proof now exists as files in the exact shape the x86 wrapper needs, not just
in-memory inside a test.

## What it produces

`cargo run -p integration_tests --example prove --release` writes to
`predicate-engine/artifacts/`:

| file | bytes | what it is |
|---|---|---|
| `proof.bin` | 223,835 | `proof.into_inner()` — the borsh-serialized RISC Zero `InnerReceipt` (the succinct receipt) |
| `journal.bin` | 696 | `output.to_bytes()` — the `PrivacyPreservingCircuitOutput` (commitments / nullifiers) |
| `image_id.txt` | 64 hex | `PRIVACY_PRESERVING_CIRCUIT_ID` — the verification key |

Run (macOS):

```
RISC0_DEV_MODE=0 \
  CC_aarch64_apple_darwin="$(xcrun --find clang)" HOST_CC="$(xcrun --find clang)" \
  cargo run -p integration_tests --example prove --release
```

## Serialization API (confirmed against source)

- `Proof(pub(crate) Vec<u8>)` with `pub fn into_inner(self) -> Vec<u8>` and
  `pub const fn from_inner(inner) -> Self`. So `proof.into_inner()` = the bytes.
- The whole `privacy_preserving_transaction` module derives borsh;
  `PrivacyPreservingCircuitOutput` has `to_bytes()`.

## The image-id correction (important — caught before the wrap)

First pass wrote `CONFIDENTIAL_PREDICATE_ID` (the predicate guest's id). **Wrong
verification key.** The proof from `execute_and_prove` verifies against the
**privacy circuit's** id, not the guest's. Ground truth in nssa
`Proof::is_valid_for`:

```rust
let inner: InnerReceipt = borsh::from_slice(&self.0).unwrap();
let receipt = Receipt::new(inner, circuit_output.to_bytes());
receipt.verify(PRIVACY_PRESERVING_CIRCUIT_ID).is_ok()
```

The predicate runs *composed inside* the circuit, so its identity is bound into
the journal/claim — not used as the top-level verify key. `PRIVACY_PRESERVING_CIRCUIT_ID`
is re-exported at `nssa::PRIVACY_PRESERVING_CIRCUIT_ID` (nssa/src/lib.rs).

**Consequence:** the Exp 3 `image_id.txt` will NOT match this one, and shouldn't —
Exp 3 was the standalone-guest path (Half A), this is the shielded path (Half B).
Different paths, different ids. Don't chase that as a bug.

This also previews the Half B coordinator work: the 696-byte journal is the
circuit output (commitments/nullifiers), so the Solana coordinator must parse
that, not a clean `EligibilityResult`.

## The wrap path is fully confirmed from source

`Proof::is_valid_for` above IS the wrap recipe: deserialize proof bytes →
`Receipt::new(inner, journal)` → operate on the receipt. The x86 wrap feeds that
reconstructed receipt to `ProverOpts::groth16()`. Half B feasibility — confirmed
from source, not assumed.
